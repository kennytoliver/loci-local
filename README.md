# Loci（忆宫）— 个人跨 Agent 记忆中枢

[English](README_EN.md) ｜ 简体中文

零依赖单文件 · 中文友好检索 · 通用 MCP 接入 · 单文件网页面板 · 数据 100% 本地

给你的所有 AI Agent 装一个**共用的大脑皮层**：WorkBuddy / Claude Code / Codex / 任何支持 MCP 的工具，读写同一份本地记忆。Agent 可以换，记忆不能丢。

**Loci 是什么** —— 一个 SQLite 文件 + 一个标准 MCP 服务 + 一个网页面板。
你的所有 Agent 读写同一份记忆；换 Agent 不用重新解释自己。

**Loci 不是什么** —— 先说清边界，省得你带着错误预期装它：

| 不是 | 因为 |
|---|---|
| **不是云服务** | 没有账号、没有 API Key、没有遥测。数据只有一个文件，在你硬盘上 |
| **不是向量库** | 零 LLM 依赖 ⇒ 不做嵌入 ⇒ 没有语义桥。**换种说法问同一件事只有 67%**（详见「[什么没有验证](#什么没有验证)」）—— 这是**架构边界，不是待修的 bug** |
| **不是聊天记录器** | **只存结论，不存原文**。对话原文进会话库（你自己回看用），记忆库存的是从里面提炼出的决策 / 坑 / 偏好 |
| **不是 Agent 编排器** | 不管谁先谁后、不管用哪个模型、不管任务队列。那是 Orbital 那类项目的事，Loci 只管记忆 |

## 为什么做这个项目

### 痛点：每换一个 harness，你就得从头解释一遍自己

同时用几个 AI 编程产品的人（Claude Code、Codex、ZCode、Kimi、Trae、WorkBuddy…），一定经历过这个循环：

- 早上在 A 里把项目背景、技术选型、踩过的坑讲清楚了；
- 中午想试试 B 家新出的模型，切过去 —— **它一个字都不知道**，得重新讲一遍；
- 晚上为了省额度换回 C，又得再讲一遍。

具体到不同的人，卡点还不一样：

| 你是哪种用户 | 卡在哪 |
|---|---|
| **多 harness 用户** | 决策原因、隐性约定、踩过的坑都留在上一个产品里，一换就失忆 |
| **模型对比测试者** | 想跑同一个任务在不同 harness / 模型下的表现，但上下文搬不过去，只能反复粘贴同一段背景 |
| **白嫖党**（靠各家免费额度过日子） | 哪家有额度用哪家，一天切换三四次 —— 每次都要重建上下文，最耗耐心 |

更麻烦的是：即使同一个产品，**换个会话也可能丢上下文**（取决于它自己的会话管理），而你没有任何办法把它导出来、存起来、带走。

### Loci 的做法：把记忆从 harness 里剥出来

记忆不该属于某个产品，它属于你。Loci 把这件事做成本地的一个 SQLite 文件，通过标准 MCP 暴露给所有 Agent：

- **换 harness 不再重置**：新 Agent 一开口调 `memory_context`，就能拿到你的常驻决策、偏好、趟过的坑；
- **反向也通**：任何 Agent 写下的东西（比如在 ZCode 里说一句"记住…"），其他 Agent 都能搜到 —— 这条链路已实测跑通；
- **不是"另一个云服务"**：没有账号、没有 API Key、没有遥测，数据只有一个文件，躺在你自己的硬盘上。

三个技术上的差异化：

1. **中文检索真的能用**：bigram 分词 + TF-IDF，中文查询命中率 5/5；
2. **标准 MCP 接入**：任何支持 MCP 的 Agent 即插即用，不需要每个产品单独适配；
3. **零依赖纯 Python**：单文件引擎 + 单文件面板，克隆下来就能跑。

不知道怎么用？看 **[USAGE.md](USAGE.md)** —— 场景化操作手册。
开头就是一张 **「我想干 X → 去哪个页面」** 的速查表，六个页面各自写了
「什么情况该用它 / 它给你什么 / 拿到之后怎么用」，还有一节「出问题怎么办」。
版本变更见 [CHANGELOG.md](CHANGELOG.md)。

## 为什么可以放心让它读你的对话

Loci 要的东西很敏感：你所有的 AI 对话历史，以及**写入各 Agent 配置文件的权限**。
一个陌生项目凭什么拿这个权限？下面四条不是承诺 —— 是你能在 30 秒内自己验证的事实：

**① 零第三方依赖：没有一行代码来自陌生人**

没有包可以被投毒，也没有依赖会在你不知情时升级。

```bash
grep -nE "^\s*(import|from) " loci.py
# 输出全是标准库：sys / os / io / json / math / re / sqlite3 / argparse / datetime / hashlib / collections
```

**② 引擎完全不联网**

```bash
grep -nE "urlopen|requests\.|http\.client|socket\.create_connection" loci.py   # 无匹配
```

唯一的网络能力在面板里，而且**只监听 `127.0.0.1` 的本地 HTTP 服务**（你自己开的那个界面）。
Agent 通过 stdio 走 MCP 协议通信，不经过任何端口。

**③ 数据就是一个文件，躺在你自己硬盘上**

没有账号、没有 API Key、没有遥测、没有云端副本。删掉即消失。

```bash
ls loci.db      # 默认与 loci.py 同目录；可用环境变量 LOCI_DB 指到别处
```

**④ 引擎全部逻辑约 3000 行，一个下午能读完**

```bash
wc -l loci.py   # ≈2980 行，含注释与 MCP 协议层
```

"单文件"这个选择是双刃的：对维护者不友好（所以拆分排在 1.1），
但对**要交出全部对话历史**的人来说，"能被完整审计"比"模块化"重要得多。

> 本项目做过一轮**外部独立代码审查**（另一个模型、另一套 toolchain），
> 从审查到逐条复核的四轮记录见 **[AUDIT-LOG.md](AUDIT-LOG.md)**。
> 平台支持边界见下方「[快速开始](#快速开始)」里的说明 —— **Windows 优先，macOS / Linux 部分功能降级**。

## 什么没有验证

上面四条讲的是"为什么可以信"。这一段讲反过来的一面 ——
**哪些东西我们没有验证过、或者验证得不充分。** 放在这里是因为：一个项目值不值得信，
不看它把能做的都做了，而看它**肯不肯把自己做不到的地方写出来**。

| 没验证的 | 具体到什么程度没验证 |
|---|---|
| **语义召回** | 换一种说法问同一件事，只到 **67%**（top-1）。中文问、英文记忆去答，**0%**。这不是 bug 是**架构边界** —— 零 LLM 依赖就等于不做向量/嵌入，不做嵌入就没有语义桥。要提升它，代价是引入第三方依赖、放弃本项目第一条承诺。**已知、已量、暂不改。** |
| **抽取质量** | 采集时按规则抽候选记忆（决策 / 坑 / 偏好 / 事实）。闸门只验了它**跑多快**，**没验它抽得准不准、漏没漏**。也就是说"该抽出来的没抽出来"这件事，现在没人盯着。 |
| **真实规模** | 闸门跑的是合成语料和临时库。**几千条记忆下的检索表现、耗时、排序质量，没有量过。** |
| **并发写入** | 多个 Agent 同时写同一个库，只**手工探过一次**（`tools/probe_concurrency.py`），之后没有持续护栏。 |
| **Windows 以外** | 回收站删除、Agent 安装路径探测都是按 Windows 语义写的。macOS / Linux 上走降级路径，**没有在那些平台上实际跑过。** |
| **长期运行** | 时间衰减有单元测试，但"用满一年之后召回变成什么样"，**没有量过**。 |
| **真实 Agent 接入** | 15 款产品的接入适配用的是构造的配置样例，**不是每种都真装一遍**。 |
| **界面正确性** | UI 闸门产出的是**截图给人过目**、量的是尺寸坐标。**"好不好看""对不对"没有自动断言** —— 靠人眼看。 |

**上面的数字是量出来的，不是估的。** 召回质量那一行来自
`tools/eval_recall.py`（22 条合成语料 / 26 个用例，含刻意构造的失败类型），
它同时作为回归闸门挂在测试套件里 —— 改坏检索会让闸门变红。

> 这一段会随版本更新。**如果哪天它变短了，说明是真的补上了，而不是删掉了。**

## 功能

| 模块 | 说明 |
|---|---|
| 11 个 MCP 工具 | `memory_save` / `memory_search` / `memory_list` / `memory_delete` / `memory_stats` / `memory_handoff` / `session_save` / `session_recall` / `memory_context` / `memory_pin` / `panel_open`（用户在对话里要求时才用） |
| 写回回执 | `memory_save` 返回的不是一句「已保存」，而是**这条到底写了什么**：内容 / 归属 / 出自哪段会话 / 怎么撤。命中去重时**如实说「没有重复写入」**（旧版本这种情况也回"已保存"，是假话）。**没有任何东西会静默进入长期记忆**（学 codex-obsidian-memory） |
| 分支感知 | 记忆可带 Git 分支（不传会自动读当前目录的 git 分支，并在回执里标出「自动探测到」）。`memory_context` **同分支优先**、其他分支降权但不隐藏；交接卡输出标注分支 —— 免得把别的分支上的试验结论当既定事实用（学 codex-obsidian-memory） |
| 省 token 的注入顺序 | `memory_context` 输出按「几乎不变的 → 偶尔变的 → 每次变的」固定排列，统计行放**末尾**（它每次都变，放前面会让整块前缀缓存失效）。开头逐字不变 → 模型商的前缀缓存能命中（学 Orbital v0.4.2） |
| 项目交接卡 | `memory_handoff` 按项目抽取决策/偏好/坑/事实，生成 markdown 注入下一个 Agent |
| 网页面板 | **6 页工作台**：**会话**（原话列表 + 独立详情页）/ **采集**（扫描勾选入库，支持一键全选）/ **交接卡**（按项目生成）/ **库**（备份·导出·恢复·销毁）/ **Agent**（体检 + 一键接入）/ **技能 · MCP**（跨 Agent 复制技能、查看并复制 MCP 配置）|
| 记忆包 | 导出为 JSON 文件，可在不同电脑/不同人之间交换记忆（导入自动去重）。**入口在「库」页的导出 / 恢复卡片** |
| 常驻记忆 | 标记「常驻」的记忆始终随 `memory_context` 返回；Agent 开聊调一次即获得跨 Agent 上下文（学 Letta core memory） |
| 记忆质检 | **七查 + 健康度评分**：重复（合并）/ 疑似同义 / 可能矛盾（以新代旧）/ 长期未更新 / 过短 / 过粗粒度（一键拆分）/ 元数据缺失；0-100 健康分；可导出 Markdown 质检报告（作废记忆保留不删除，学 Zep）。⚠️ 能力在引擎与 CLI 层，**界面不再单独设页**（记忆是给 Agent 读的，人逐条读没意义）；面板只在会话页用「待质检」角标提示 |
| 记忆转技能 | 把项目记忆导出成 SKILL.md 写进各 Agent 的 skills 目录（Mem2Skill 思路） |
| 会话→记忆 | 从归档会话按规则抽取候选记忆（决策/坑/偏好/事实），勾选入库，零 LLM 依赖 |
| 会话层 | 归档对话原文（会话库存过程与原话，记忆库存结论），支持粘贴/文件/JSONL 导入、时间线回看、原话检索，重复内容自动去重 |
| 采集中心 | 扫描本机 Agent 历史日志与 skills，人工勾选后入库（去重+白名单校验） |
| Agent 体检 | 面板自动检测本机安装了哪些 Agent、哪些已接入 Loci |
| 一键接入 | 覆盖 15 个产品 —— **12 个可直接写入配置**（WorkBuddy / ZCode / Kimi Code / DeepSeek CLI / Trae / TraeWork / VS Code / Cursor / Windsurf / Gemini CLI / Qoder / CodeBuddy），**3 个仅检测**（Claude Code / Codex / GitHub Copilot CLI，请按各自官方方式手动接入）；写入前自动备份、只合并不覆盖、可移除（ZCode 使用嵌套 mcp.servers 结构） |
| CLI | 交互式命令行 + 单条命令两种模式 |

## 快速开始

**环境要求**：Python 3.9+，零第三方依赖。

> **平台支持**：本项目 **Windows 优先**。回收站删除（走系统 Shell API）、Agent 安装路径探测、
> 面板进程启停等按 Windows 语义实现；macOS / Linux 可以运行，但上述功能会**降级**
> （例如"删除"改为移入同目录 `.trash`，不保证进系统回收站）。

```bash
git clone https://github.com/kennytoliver/loci-local.git
cd loci-local
```

**方式一：网页面板（推荐）**

```bash
python panel.py --open        # 自动打开浏览器
# 或
python panel.py --port 8787   # 手动访问 http://127.0.0.1:8787
```

> **面板不常驻**：页面开着就算在用；关掉浏览器页面后 5 分钟无访问会自动退出
> （也可以点右上角 ⏻ 立刻退出）。
> 想让它一直开着：`python panel.py --idle-exit 0`。（记忆本体不受影响 —— Agent 照常读写）

> **面板默认不会自己弹出来**：Agent 读写记忆时，面板**不会**自动打开。
> 想打开有两条路：① 自己跑上面的命令；② 在对话里说一句「打开 Loci 面板」—— Agent 会调
> 工具 `panel_open` 替你打开。
> 想让它更自动一点，用环境变量 `LOCI_PANEL` 调档：
> `explicit`（默认，只有你明确要求才开）/ `write`（另外：真的写入记忆之后也开）/
> `auto`（MCP 服务一启动就开）/ `off`（一律不开，只做记忆、不碰界面）。
> ⚠️ 早期的 `auto` 档做过默认，结果**一打开任何 Agent 产品面板就跳出来**（因为一开会话
> Agent 就会读上下文）—— 那是在说"你启动了一个 Agent"，不是"你在用 Loci"，所以改了。

**方式二：接入 Agent（MCP）**

最省事：打开面板 → **Agent 体检** → 对已安装的 Agent 点「**一键接入**」。面板会自动写入对应的 MCP 配置（先备份、只合并不覆盖），并提供「移除接入」与「验证 MCP 服务」。

手动配置（面板未覆盖的客户端）：

Claude Code：
```bash
claude mcp add loci -- python -X utf8 /path/to/loci.py
```

其他 MCP 客户端：command 指向你的 Python，args 为 `["-X", "utf8", "/path/to/loci.py"]`，环境变量 `LOCI_DB` 可指定数据库位置（默认 loci.py 同目录）。

**方式二·补充：命令行安装器（不用面板）**

```bash
python install_agents.py --list        # 扫描本机装了哪些 Agent
python install_agents.py --all         # 一键接入全部（写前自动备份）
python install_agents.py --verify      # 真实 MCP 握手验证
python install_agents.py --rules       # 写入「记忆使用约定」，让 Agent 开局先调 memory_context
```

**方式三：命令行**

```bash
python loci.py --cli                                # 交互模式
python loci.py --save "写操作先落库再失效" --type skill --proj 架构
python loci.py --search "缓存怎么失效"
python loci.py --stats
```

## 测试

```bash
python test_mcp.py     # 引擎端到端测试：握手/工具列表/写入/中文检索/交接卡/统计/负例
python test_panel.py   # 面板回归测试：JS 语法守卫/元素完整性/路由齐全/零依赖
```

**完整套件：26 项闸门**

```bash
bash tools/run_gates.sh          # 全跑
bash tools/run_gates.sh eval_recall   # 只跑某一项（这里是召回质量）
```

其中 `eval_recall` 是**召回质量回归护栏**，也是唯一一项衡量"记忆找得回来吗"的闸门 ——
基线写在 `tools/eval_recall.py` 里，**低于基线就变红**。
其余 25 项验的是契约、存储、界面接线与观感，**它们都验不到召回质量**
（这正是「[什么没有验证](#什么没有验证)」那一节的第一条）。

## 隐私

所有数据保存在本地 SQLite 文件中，不联网、不上云、无遥测。面板只监听 `127.0.0.1`。

**请知悉**：这是本机单人使用的工具。数据库是一个普通文件，因此**同机任何能读到它的进程都能拿到全部记忆内容** —— 「跨 Agent 可见」和「无访问隔离」是同一件事的两面。若你机器上有多个用户或不信任的进程，请自行用文件权限保护该文件。
